# 0.10.0 release preparation

Status: stable release prepared locally; not tagged or published. Prepared from
`develop` commit `29f4169aa0af4ab73dab918022ca055a72e7a558` on 2026-09-29.

The user explicitly chose to skip the RC channel for this release after the
development smoke tests passed. This overrides the usual RC-first sequence in
[RELEASING.md](../../RELEASING.md) for 0.10.0 only; publication still requires
explicit approval.

## Scope and contracts

- Minimum Python version moves from 3.9 to 3.10; supported versions are 3.10–3.13.
- Add twelve text analyzers and keyword facets, including optional queries,
  facet-only requests, typed models, and facet preservation through `docsUrl`.
- Include the query-score regression harness. The server fixes the `"NaN"`
  response issue; this SDK release does not normalize those strings.
- Refresh the development lock from AnyIO 4.9.0 to 4.15.1 and typing-extensions
  4.16.0. AnyIO's open repository advisories identify 4.14.2 as the first patched
  version. This overlaps the lock update proposed by [PR #43](https://github.com/lambdadb/lambdadb-python-client/pull/43);
  that PR is not merged by this release preparation. Published runtime dependency
  ranges are unchanged, and the Poetry lock does not control consumer pip installs.

The implementation uses scoped contract pins, rather than claiming every change
in an intervening OpenAPI revision was ported:

| Scope | Exact revision |
| --- | --- |
| Base Data Versioning API / `API_CONTRACT_REVISION` | docs `c44180406c05b1a9043d8516e7c7f60df91fc9a7` |
| Analyzer extension | docs `3bda642f2e7f4f26432f1dfdcb076f656d50f873`; backend `410154abcdf5275add1df47dcf23c170ed0e0efd` |
| Keyword facets | docs `899092420ff801cfcb3b693b1ba273be7ac1f1ef`; backend `8da50bcd0b5a3c781ffccd7f01fb07ed0510dd30` |

See [analyzer maintenance](../../schemas/README.md) and
[keyword facets](../keyword-facets.md). Existing keyword indexes and old Tags
require a complete rebuild into a new Collection for the new format.

## Environment smoke tests

The installed stable wheel was tested on the configured development API
(`bench-recall` test project) on 2026-09-29. Deployment completion was reported
by the user; the exact deployed server SHA has not been independently identified.
This is not a production deployment or published-package validation.

| Check | Result |
| --- | --- |
| Query score / facets / sync / async / inline / docsUrl | 30 valid cases passed; 6 invalid combinations skipped |
| Data Versioning live lifecycle | passed |
| Qdrant compatibility live smoke | passed |
| LangChain and LlamaIndex compatibility | 4 passed against fake LambdaDB transport |
| Analyzer acceptance and representative term query | all 16 passed on the earlier local RC build; unchanged implementation |

The stable-wheel integration run finished with 36 passes and 6 skips in 186.99
seconds. All optional integration dependencies were installed. The six skipped
combinations are `size=0` without facets, which is not a valid
score-contract request.

External versions: qdrant-client 1.19.1, langchain-qdrant 1.1.0,
llama-index-vector-stores-qdrant 0.10.3, and llama-index-core 0.14.25.
The wheel tests used Pydantic 2.13.5, httpx 0.28.1, and AnyIO 4.15.1; the Poetry
locked environment also passed its 225 non-integration tests with Pydantic 2.11.5.

Analyzer evidence is retained from the earlier local `0.10.0rc1` build, which
was never published. A byte comparison of both wheels confirmed that
`version.py` is the only changed package file. The first analyzer smoke attempt
received HTTP 503 on the first query after
creation/upsert, then deleted its temporary collection. A second attempt used
bounded readiness polling (up to 90 seconds per field), observed one initial
503, and passed all 16 representative term queries. This verifies schema
acceptance and basic matching, not broad linguistic relevance quality. The
initial service-unavailable responses are retained as operational observations.

Query-less responses omit score fields; queryString controls retain finite
numeric scores. Query-score and analyzer collections were confirmed absent with
HTTP 404. A post-run Collection listing found no remaining temporary Collection
names with the versioning, Qdrant smoke, score smoke, or analyzer smoke prefixes.
