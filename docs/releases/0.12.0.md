# 0.12.0 release preparation

Status: stable release prepared for review; not merged to main, tagged, or published.
Source: reviewed `develop` commit `d807bb19ca52587a6fb037badd54a8584139aa15`
([API support PR #49](https://github.com/lambdadb/lambdadb-python-client/pull/49)).
Release branch: `release/0.12.0`, targeting `main`.

On 2026-10-06, Steven explicitly requested preparing the stable release directly,
without development or RC releases. This overrides the dev/RC sequence in
[RELEASING.md](../../RELEASING.md) for 0.12.0 only. RC-specific installation checks
are not applicable to this exception. Merge, tag creation, and publication still
require separate authorization; no general release policy or workflow is changed.

## Release notes

- Add `candidate_size` to all sync/async query methods and the request model/TypedDict.
  Bayesian retrieval without rerank requires `1 <= size <= candidate_size <= 100`.
  With rerank, omit the top-level budget and use the existing rerank budget/default.
- Preserve free-form queries and server HTTP 400 classification for invalid signal
  counts, boosts, nested fusion, and budget combinations. Bayesian uses exactly
  two unboosted signals; ordinary text/KNN/RRF/Min-Max/L2 requests remain unchanged.
- Accept native `embedding` configuration without `managedEmbedding` in collection
  create/update. Retain legacy true inputs, existing public models, normalized
  response metadata, and caller-provided vector behavior.
- Omit unspecified embedding similarity on the wire while retaining the existing
  cosine model attribute default. Put native dimensions/similarity inside embedding.
- Preserve `retrievalScore`, rerank status, and automatic result downloads. No
  client defaults, fusion weights, provider credentials, or CLI are introduced.
- Python support remains 3.10–3.13. Dependency ranges and publishing workflows
  are unchanged. See [usage and compatibility](../bayesian-native-embeddings.md).

The scoped backend contract is pinned to
`9072a1bc8925954369a887f558f1eaf387b7ea0e`. The base Data Versioning API pin and
existing analyzer/rerank/facet pins remain unchanged. A source pin does not
establish availability in production or another environment.
