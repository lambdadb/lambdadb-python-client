# 0.12.1 release validation

This record describes pre-publication validation of the terminology-only patch.
Source: reviewed `develop` commit `d5639031349f29ae41243501626a081540993389`
([terminology PR #51](https://github.com/lambdadb/lambdadb-python-client/pull/51)).
Release branch: `release/0.12.1`, targeting `main`.

On 2026-10-07, Steven requested branch cleanup and a direct stable release without
an RC. This is a release-specific exception to the RC-first sequence in
[RELEASING.md](../../RELEASING.md); it does not change the general release policy.
RC-specific installation checks do not apply. The earlier instruction not to run
paid or state-changing live smoke tests solely for this terminology cleanup
remains in effect.

## Scope and compatibility

- Standardize native embedding and native reranking terminology in documentation,
  SDK descriptions, examples, and internal test names.
- Rename the reranking guide and scoped schema files and update repository links.
- Preserve public symbols, wire fields, configuration keys, error strings,
  legacy behavior, and pinned external paths and identifiers.
- No changes to parsing, validation order, error classification, serialization,
  defaults, candidate/resource limits, dependencies, or publishing workflows.
- Set both package version sources to `0.12.1`; the user-agent version follows
  the existing runtime version function.

Contract pins remain unchanged: base Data Versioning docs
`c44180406c05b1a9043d8516e7c7f60df91fc9a7`, Bayesian/native embedding backend
`9072a1bc8925954369a887f558f1eaf387b7ea0e`, and reranking backend
`55d888299fee44466326a9db8016af9811ade13b`. Existing analyzer/facet pins are also
unchanged. These identify source contracts, not current deployment.

source byte-for-byte. Comparison against the published `0.12.0` wheel confirms
identical ASTs after removing documentation strings and normalizing only the
`SDK_VERSION` value. No executable behavior changes are hidden in this patch.

`b70f60fbdb7162678dca396ee1318b00acc4313dcda5261f1bc545404f1f320b`, matching the

with fake transports, without server mutations or paid provider requests:

```bash

```

Versions: qdrant-client 1.19.1, langchain-qdrant 1.1.0,
llama-index-vector-stores-qdrant 0.10.3, llama-index-core 0.14.25.
Wheel runtime tests used Pydantic 2.13.5 and httpx 0.28.1.

Live behavior evidence is retained from the `0.12.0` release record: 35 actual
server tests passed against shared dev, including native embedding and reranking,
plus four external compatibility tests. The successful pinned backend
[deployment run](https://github.com/lambdadb/lambdadb/actions/runs/37422611173)
was re-read and confirms revision `9072a1bc8925954369a887f558f1eaf387b7ea0e`.
This is historical deployment evidence; current ECS tasks were not revalidated.

No live smoke was repeated for this terminology-only patch, consistent with the
user's instruction and the executable-equivalence check above. This record does
not claim new live-server, ranking-quality, performance, or production-deployment
validation. Publication status is tracked by the GitHub Release and PyPI.
