# 0.13.0 release validation

Source: `develop` commit `3973384b843d3a6d1478a46d3bb3ccbdd0a0f1ab`
([SDK alignment PR #54](https://github.com/lambdadb/lambdadb-python-client/pull/54)).
Release branch: `release/0.13.0`, targeting `main`.

On 2026-10-26, Steven explicitly requested a direct stable release without an
RC. This is a release-specific exception to the RC-first sequence in
[RELEASING.md](../../RELEASING.md), not a change to the general release policy.
RC-specific installation checks do not apply.

## Scope and compatibility

- Support Query/rerank budgets up to 1000 and List requests up to 1000 while
  retaining default pagination of 100, optional-field omission, and `knn.k`.
- Add `ListDocsResponse.documents` and share envelope discrimination with
  sync/async pagination, preserving application fields named `doc`.
- Follow the public vector contract: dimensions 64-4096 and cosine/euclidean.
  Remove `Similarity.DOT_PRODUCT` and `Similarity.MAX_INNER_PRODUCT`; Qdrant
  DOT and Manhattan configurations remain unsupported. These restrictions
  also apply to collection metadata parsing. Existing out-of-contract
  collections can raise `ResponseValidationError`; follow the
  [migration requirements](../vector-configuration.md) before upgrading.
- Document native embedding/reranking stored source paths without requiring
  source index declarations, and repair outdated SDK reference text and links.
- Refresh the locked test CA bundle to certifi 2026.10.23 without changing
  runtime dependency ranges or publishing workflows.
- Change only release metadata and upgrade documentation relative to the
  reviewed SDK implementation. Both version sources are `0.13.0`.

## Production smoke

The installed `0.13.0` validation wheel passed **38 actual production tests**
in 331.60 seconds. Six invalid facet-only combinations were intentionally
skipped and 15 non-integration checks were deselected. The command was:

```bash
/tmp/lambdadb-release-0.13.0/py3.12/bin/python /tmp/lambdadb-release-0.13.0/prod/run_smoke.py
```

The external scratch harness loaded the authorized `.env.local` without printing
credentials, asserted the intended production URL/project, and invoked the
maintained Bayesian/native, Qdrant, Data Versioning, and query score/facet suites
with their four explicit opt-in flags. Pytest used `-m integration -o pythonpath=`
to import the installed wheel. A bounded additional test covered List document
access and sync/async pagination with object-valued application `doc` fields.

Coverage included actual document/query embeddings and native reranking,
unindexed top-level/nested source paths, unsupported raw native vector HTTP 400,
partial-update/replacement behavior, Branch/Tag/Alias lifecycle, signed bulk
upload, and inline/gzip `docsUrl` score/facet responses in sync/async APIs.

All nine temporary collections were deleted and individually verified absent
with HTTP 404. The project began and ended with zero collections. This smoke
does not establish ranking quality, throughput, or full-depth 1000-candidate
rerank success; the earlier bounded limit investigation is separate evidence.

## Known server limit

The earlier production investigation recorded HTTP 408 for 1000 actual rerank
candidates with the deployment's 2000 ms stage budget. `returnOriginal` returned
a timeout fallback with zero scored candidates. The request-count maximum does
not guarantee full-depth reranking within that deadline. This release preserves
server errors and fallback metadata; it introduces no implicit truncation,
smaller candidate budget, retry, or fallback. See
[bounded production evidence](https://github.com/lambdadb/lambdadb-python-client/pull/54)
for successful 1000-document retrieval and the separate rerank timeout.
